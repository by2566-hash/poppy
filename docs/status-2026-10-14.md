## 2. How one run works

Every arm uses the same unit: **one OpenCode run in its own folder**.

1. The Python harness creates a sandbox folder with:
   - `data/crashes.parquet` (link to our snapshot), an empty `out/`;
   - `opencode.json` that limits the agent: shell may run only `python3`, `ls`, `cat`, `head`, `mkdir`; no web; no access outside the folder; at most 15 steps.
2. It starts OpenCode non-interactively:
   ```bash
   opencode run --pure --print-logs --log-level ERROR --format json \
     -m opencode/<model> --dir <sandbox> -- "<prompt>"
   ```
   with stdin closed and a private data directory (`XDG_DATA_HOME`) so runs can go in parallel.
3. Inside OpenCode the model works in **steps**. Each step is **one request** to the model provider: the model writes code, OpenCode runs it, the result goes back to the model, and so on, until the model writes a final reply or reaches the step cap. OpenCode also sends one small extra request per session to name it.
4. The harness reads OpenCode's JSON events (steps, tool calls, tokens, final text), saves `meta.json`, and checks the artifacts: `out/initial.png`, `out/values.csv`, and the `ANSWER:` line.
5. Scoring compares `values.csv` with the gold numbers from our own SQL and reads the answer (gate: correct and not misleading).

The arms differ only in what is sent:

| Arm | Runs per item | What changes |
|---|---|---|
| A | 1 | plain prompt |
| C | 1 | same prompt + one generic self-check instruction |
| B | 3 | A's run, then a **critique** run that reviews A's chart, values, code and answer, then a **revise** run that rewrites and re-runs the code |

So "one run" is not "one request": a run takes 6–16 requests. **We sent about 830 requests to mimo in roughly a day.**

## 3. Why runs got stuck: three different causes

| Symptom | Cause | Status |
|---|---|---|
| Whole batch "hangs", no output, every item hits the timeout | **stdin left open**: `opencode run` reads piped input and waits for it to end. A batch started in the background never closed it | Fixed: stdin closed (`stdin=DEVNULL`) |
| Replies say "maximum steps reached… recommended next step" instead of answering | A **one-step limit** we tried, to force a single call, injects that message; the model narrates instead of answering | Abandoned; we use a 15-step budget, and a reply produced by the cap counts as "not completed" |
| Calls never return; event stream empty; looks like a hang | **Rate limiting by the OpenCode free tier**: `Rate limit exceeded`. OpenCode retries 3 times and keeps waiting, so nothing shows up in the output; the message appears only in the logs | Harness now detects it within seconds, stops, backs off and retries; rate-limited items are not scored |

So: OpenCode's output was fine and our pipeline was not the bottleneck. **We were rate-limited by the free tier, per model**: mimo and big-pickle stopped answering for 45+ minutes while nemotron kept working. What we do not know yet is whether the limit is per machine/IP, per model for everyone, or daily.

## 4. Try it yourself

Setup (once):
```bash
git clone https://github.com/by2566-hash/poppy.git && cd poppy
pip install duckdb pandas pyarrow matplotlib
curl -L -o data/raw/nyc_crashes_h9gi-nx95.csv "https://data.cityofnewyork.us/api/views/h9gi-nx95/rows.csv?accessType=DOWNLOAD"
python3 experiments/E001-data-card/run_experiment.py      # builds data/processed/nyc_crashes.parquet
```
OpenCode must be installed (`opencode --version`); no account or key is needed for the free models.

Step 1 — check the free models from your machine (≈ 2 requests per model):
```bash
python3 scripts/check_free_models.py
```

Step 2 — one pilot question, arm A, with a model that is OK for you (≈ 8–15 requests):
```bash
POPPY_MODEL=nemotron-3-ultra-free PILOT_QIDS=K1 python3 experiments/E007-pilot-prompts/run_pilot.py A v1 1
```
Results land in `../poppy-sandbox/E007/A-v1-<model>/K1-r1/` (`out/initial.png`, `out/values.csv`, `response.md`, `meta.json`). Gold numbers are in `experiments/E007-pilot-prompts/gold_pilot.json`.

Please do **not** start full batches yet: each run costs 6–16 requests and we do not know the limit.
