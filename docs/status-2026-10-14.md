## 2. What the pilot round is for, and how we accept it

**Purpose:** make B's two steps work as designed, then freeze the A and B prompts.

- **Review (③)** is an honest review, not a re-analysis: it finds real problems, does not invent any, and says so when it finds none.
- **Revise (④)** changes only what the review flagged and never turns a correct answer into a wrong one.

C is not part of the pilot: Bo writes C's prompt after A and B are frozen, using what B's reviews found, and checks it once for format.

**Acceptance** (6 pilot questions, 1 run each per iteration, at most 3 iterations):

| Step | Pass if |
|---|---|
| Review | ≥ 5/6 give a numbered `ISSUES:` list (or `ISSUES: NONE`); ≥ 5/6 use ≤ 2 tool calls; where A was wrong, at least half name the real error; where A was right, no invented substantive error |
| Revise | ≥ 5/6 produce a revised chart and values (or are correctly skipped); every number A had right is unchanged; **zero right → wrong flips** |

Full rules: `experiments/E007-pilot-prompts/PROTOCOL.md`. Questions and gold numbers: `pilot_questions.json`, `gold_pilot.json`. **Please read the acceptance table and suggest changes.**

## 3. How one run works

1. The runner makes a folder for the item: a link to the data, an empty `out/`, and `opencode.json` copied from `experiments/E007-pilot-prompts/config/`.
2. It starts `opencode run --pure --format json -m opencode/mimo-v2.6-flash-free --dir <folder> -- "<prompt>"` (stdin closed, logs on, private data directory).
3. The model works in **steps**. One step = one request to the model: write code, OpenCode runs it, the result goes back, next step — until it answers or reaches **15 steps**.
4. The runner saves the event trace, `meta.json` (steps, tool calls, tokens, versions, prompt fingerprints) and the artifacts: `out/initial.png`, `out/values.csv`, the `ANSWER:` line.

| Arm | Runs per item | Prompt |
|---|---|---|
| A | 1 analysis run | `prompts/A.v1.md` (frozen) |
| B | A's run + 1 review run (no code execution; chart attached, values/answer/code embedded) + 1 revise run only if issues were found. **B runs only if A produced an `ANSWER:`; otherwise the item fails in both arms.** **B reads A's output from the repo (`experiments/E007-pilot-prompts/results/<A_label>/`), so A's results must be collected and committed before B is run** | `prompts/B_critique.v2.md`, `prompts/B_revise.v2.md` |
| C | 1 analysis run | written after the freeze |

**Why 15 steps:** clear questions used ≤ 11; ambiguous questions hit a 10-step cap 8 times out of 12, and 15 rescued one more at +33% time. It is a **per-run** budget, the same for every run. B makes up to three runs per item, so it spends more in total; we report that as B's cost next to its effect, not hide it.

A run is 6–16 requests, not one. That is why we hit the free-tier limit.

## 4. Same environment for everyone

Setup once (macOS):
```bash
git clone https://github.com/by2566-hash/poppy.git && cd poppy
pip install -r requirements.txt
curl -L -o data/raw/nyc_crashes_h9gi-nx95.csv "https://data.cityofnewyork.us/api/views/h9gi-nx95/rows.csv?accessType=DOWNLOAD"
python3 experiments/E001-data-card/run_experiment.py
python3 scripts/check_env.py
```
`check_env.py` must print **READY**. It checks OpenCode **1.18.34**, Python ≥ 3.11, the pinned packages, and the data **content fingerprint** (2,269,187 rows and checksums in `scripts/env_expected.json`). A different OpenCode version is a FAIL: install 1.18.34 before running. Every run also records these versions in its `meta.json`.

## 5. Rate limit: what we know and what we need to find out

The free tier answers `Rate limit exceeded`; OpenCode retries silently, so it looks like a hang. The runner now detects this within seconds, stops, backs off (90 s, 240 s) and does not score rate-limited items. Default concurrency is 1 (`PILOT_CONCURRENCY`).

**Unknown:** is the limit per machine/network or per model for everyone? If it is per machine, we can split the formal runs across our three laptops.

## 5b. No internet for the model (fixed 2026-10-15)

Chloe found that A-v1's I1 runs downloaded vehicle-mile data (`websearch` tool, `urllib` in python). The design allows only the data file. Fix: `websearch: deny` in both configs, and the model's `python` now runs under macOS `sandbox-exec` with outbound network denied; this also forces the pinned interpreter (the PATH problem). `check_env.py` now checks `sandbox-exec`. Runs made before the fix: A-v1 I1 r1/r2 are void and will be re-run; no other E007 run used the network (E004 big-pickle Q02/Q03 did, corrected in its report). Every run now records `net_calls` in meta.json as an audit.
